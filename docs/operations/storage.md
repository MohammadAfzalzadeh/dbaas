# Storage safety

PostgreSQL keeps `pgdata-<release>-patronimvp-<ordinal>` claims; MinIO keeps `data-<release>-minio-statefulset-<ordinal>`. Claim template names, controller selectors and governing Services are preserved from Phase 1/2. Each member has a separate volume. `postgres.storageClass`/`storageCapacity`/`accessModes` and corresponding `minio.*` values are configurable for new installations. Default access mode is ReadWriteOnce. ReadWriteOnce does not itself prevent two pods on one node from mounting a claim. CSI support determines whether ReadWriteOncePod is usable; do not switch modes on a live claim.

Ordinary StatefulSet deletion/uninstall retains claims by Kubernetes default. `explicitRetainPolicy: true` emits Retain/Retain on Kubernetes >=1.27 only. The feature gate/cluster API must also support this field; default omission supports older servers. This does not override the underlying PV reclaim policy: if an operator or recovery workflow deletes a PVC, a Delete-class PV may destroy its storage. Inspect StorageClass, PV reclaim policy and CSI snapshots before changes. [Kubernetes StatefulSet retention](https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/#persistentvolumeclaim-retention).

Helm changes to volumeClaimTemplates usually cannot be patched. Increase actual PVC size only if the StorageClass supports expansion; watch filesystem resize and all replicas, and handle the StatefulSet template separately through a reviewed controlled recreation. Never shrink a volume. Changing class/access mode requires new storage and verified migration; merely changing values is insufficient.

Recovery preflight checks exact names, namespace, labels, ownership, Bound state, UID and consumers. Execute explicitly removes selected PostgreSQL claims after stopping workloads. MinIO backup storage must survive; never delete its claim alongside the cluster being restored. Keep backups outside the database failure domain. Current single-server MinIO on the same Kubernetes installation does not meet that goal for whole-cluster loss.

Before uninstall/migration: inventory PVC/PV UIDs, volume handles, class, capacity and reclaim policy; verify backup objects and a separate restore; retain original Helm values securely. Never use broad label deletion against data. See [migration](migration-phase3.md) and [upgrade steps](upgrades.md).
